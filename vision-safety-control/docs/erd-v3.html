2차에서 바뀐 점

  1. education · worker_education: 새 테이블: 안전교육 목록과 작업자별 이수 이력
  2. worker: 특별관리 사유 여러 개(JSON) · 메모 · 지정일 · 지정한 사람, 현장 투입일
  3. users: DELETED 상태 추가 (처리 기록 때문에 행은 남김), 5번 틀리면 15분 잠금(locked_until)
  4. equipment: 등록번호 · 제원 · 소속 회사, 레미콘 · 덤프 유형, 상태 OUT → BROKEN(고장)
  5. work: work_date → start_date · end_date (여러 날 작업), 작업 내용
  6. alert_rule: is_active: 끄면 그 유형은 이벤트를 만들지 않음
  7. equipment_daily_log: 운전 전 점검 시각(inspected_at)

읽는 법

→ camera 처럼 FK 옆에 가리키는 테이블이 붙어 있습니다. 가리키는 쪽이 N, 가리켜지는 쪽이 1 입니다. 예: 카메라 1대에 이벤트 여러 건.

TC 경보는 event → camera → equipment 로 따라가 어느 크레인인지 찾습니다.

경보 하나가 처리되는 흐름 예: TC 3호기 인양물 직하부 작업자

1 TC CAM이 감지camera (view_page = 2)
→
2 규칙 적용 · 이벤트 생성roi_rule → alert_rule → event
→
3 관제화면 알림 · 크레인 표시camera.equipment_id
→
4 항목별 작업 허가release_check_item → event_action(PERMIT)
→
5 모두 허가되면 해제event_action(RESOLVE) · status = DONE
